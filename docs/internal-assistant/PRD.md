# 内部智能客服｜知识检索与问答 PRD

版本：v1.0 · 2026-10-26 · 需求设计基线，待实现与验证

为内部人员查找充电宝整机保护功能知识，回答可追溯、范围可说明。

## 01 产品目标与首版范围

服务内部产品、研发和测试人员，围绕充电宝整机保护功能及相关规格、适用标准和公司规范，提供搜索与单轮知识问答。主要价值是帮助使用者找到正确依据、理解内容并缩短完成资料查找任务的时间。

| P0 | P1 | 本版不做 |
| --- | --- | --- |
| 资料搜索、单轮 RAG 回答、引用定位、缺证及冲突提示、简单反馈 | 多轮上下文、复杂查询规划、完整反馈运营中心 | 面向消费者的售后客服、其他硬件领域、联网补标准、自动认证和技术放行。 |

与 AI Work 共用受控知识底座，但按问题检索与组织答案；不能用问答成绩替代报告核对成绩。共用规则见[知识库与 RAG 共用规范](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/docs/shared/knowledge-base-rag.md)。

## 02 用户与典型任务

| 用户任务 | 输入例子（场景示意） | 需要交付的结果 |
| --- | --- | --- |
| 查找资料 | 搜索某份规格书或某保护测试项目 | 相关文件、适用版本、命中片段与原文入口。 |
| 理解要求 | 某项测试要记录哪些条件和结果？ | 按所选资料回答，并引用具体章节或页码。 |
| 查证参数 | 某型号的一项参数要求在哪里？ | 在型号匹配前提下提供要求与来源；不跨型号拼接。 |
| 辨别资料差异 | 两份内部规范对某项要求是否一致？ | 在明确选择的资料之间展示差异，不擅自确定适用优先级。 |

以上均为产品使用场景示意，未声称已有真实问题日志。用户必须有相应资料访问权限。

## 03 页面信息架构与交互

| 区域 | P0 内容 | 交互约束 |
| --- | --- | --- |
| 问题与搜索输入 | 自然语言或关键词，支持选择仅搜索或生成回答 | 空输入不提交；超过配置长度说明如何缩短，不截断关键条件后静默运行。 |
| 范围条件 | 领域固定；按任务需要选择型号、资料、版本 | 保持当前请求明确的条件；单轮不默认继承上一问条件。 |
| 搜索结果 | 文件名、版本、来源类型、片段与定位 | 可以先看结果；不强制生成长回答。 |
| 回答内容 | 直接回答、必要条件、证据缺口和引用 | 结构服务问题本身，不向普通用户展示向量参数或模型分数。 |
| 原文查看 | 授权文件及章节、页码或表格位置 | 点击时再次检查访问权；失效引用有明确说明。 |
| 简单反馈 | 有用或有误、错误类型、可选备注 | 错误类型含错答、引用不符、检索遗漏、资料缺失；不直接发布新知识。 |

第一版可保留单次请求结果供当前会话查看，但不承诺跨轮语义记忆。再次提问按新请求处理，界面明确说明需要重新选择的条件。

## 04 输入理解与澄清

1. 识别检索意图：找文件、找要求、解释内容或对指定资料作比较。
2. 提取问题中明确给出的型号、测试项目、参数、单位、标准及版本。
3. 对不影响回答的缺失条件不反复追问；影响适用性时提出具体补充项。
4. 允许给出能确认的局部回答，同时标出尚不能判断的部分。
5. 首版不将全套报告检查包装成一次问答；需要逐项评审时引导进入 AI Work。

| 输入情况 | 预期行为 |
| --- | --- |
| 用户只输入标准名称 | 优先提供可访问资料与版本入口，不猜测他想要的技术结论。 |
| 问“这个是否满足要求”但无对象 | 请补充对象与依据；可提供相关知识入口。 |
| 有多个型号或版本可匹配 | 列出必要区别，让用户选择，避免跨对象拼接。 |
| 超出充电宝整机保护范围 | 说明当前范围；不伪装知识库已覆盖。 |

## 05 本模块完整 RAG 链路

1. 资料准备：使用已解析、审核发布并带来源、版本与原文定位的知识。
2. 查询处理：保留术语、型号、数值与单位，必要的同义表达归一不得改变原始含义。
3. 检索前过滤：应用当前身份、已发布状态、领域、型号和用户明确选择的版本条件。
4. 候选召回：结合关键词和向量语义检索；具体配置通过代表性问题对照测试。
5. 排序与上下文补充：优先适用且能直接支持问题的证据，补齐表头、注释或条款上下文。
6. 证据组织：区分标准、公司规范、规格书和其他资料；保留出处，发现冲突时并列。
7. 答案生成：在证据支持范围内回答；保留关键条件，引用绑定到具体结论。
8. 引用核验与后处理：检查文档版本、定位与支持关系；无法核验的结论降为无法确认。
9. 记录与评测：保存查询、范围、证据、输出、失败、耗时与反馈，支持离线回放。

完整数据处理和索引生命周期见[知识库与 RAG 共用规范](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/docs/shared/knowledge-base-rag.md)。P0 可配置的参数包括切分策略、召回数量、排序、证据预算、超时与有限重试；本文不预设未经验证的最优值。

## 06 回答规则

| 情形 | 输出要求 |
| --- | --- |
| 有足够适用证据 | 先回答问题，再给必要条件和引用；不把原文片段堆砌成答案。 |
| 只支持部分问题 | 分别标明可确认与缺少依据的部分。 |
| 检索未命中 | 说明在当前范围内未找到资料；建议补充名称、型号、版本或向知识维护者提交缺口。 |
| 证据相互冲突 | 说明哪份资料在哪个条件下怎样不同，不自动按“最新”或“更严格”裁决。 |
| 问题涉及推断 | 明确标明推断及其依据；无法验证的重要技术判断不输出确定答案。 |
| 资料可能过期或适用性不明 | 显示状态与限制，请求选择适用资料；不静默混合。 |

没有充分依据时，不使用模型记忆编造条款、阈值、文件名和出处。不把检索相似度显示为答案正确概率。

## 07 引用与资料卡片

- 引用绑定到被支持的语句或结论，至少保存 document_id、version_id、chunk_id 及原文定位。
- 显示资料名称、版本、来源类型和 PDF 页码；有条款号或表格位置时同时保留。
- 保存文件页序与印刷页码两套字段，无法确认印刷页码时只显示可定位的文件页序。
- 引用卡片提供必要上下文，避免用户只看到孤立阈值而遗漏适用条件。
- 引用能打开不等于支持结论；评测需要检查支持关系。
- 原文下载、片段、缓存答案和引用访问均受权限控制。

用户不能访问的资料不进入上下文，不能在回答中泄露标题、片段或内部存储路径。

## 08 版本、范围和知识更新

- 查询明确指定版本时，只在被授权且符合范围的该版本中搜索；历史版本可被明确选择，但界面保留其状态。
- 未明确指定版本时按当前已发布的适用知识快照检索；存在多个适用候选且会改变答案时澄清。
- 管理员发布新版本前需检查解析、适用范围与回归结果；发布成功后切换检索可见版本。
- 停用资料从默认检索中排除；历史回答仍记录原依据版本，不能无痕改写。
- 反馈只形成纠错记录，经过审核的资料才可加入正式知识。

第一版的审核和发布可由管理员线下确认并通过工具执行，不要求完整审批界面。

## 09 请求状态、异常与恢复

| 状态或触发 | 页面与服务行为 | 恢复 |
| --- | --- | --- |
| 检索中 | 展示正在搜索资料；用户可先查看已返回片段 | 同一次请求使用 request_id 关联。 |
| 生成中 | 展示已有引用来源；输出须标明尚未完成 | 中断后不把残缺回答标为完成。 |
| 已完成 | 回答、引用、所用范围和反馈入口可查看 | 下一问作为独立请求。 |
| 待补充 | 展示缺失的关键条件 | 用户补充后新请求明确包含这些条件。 |
| 无充分依据 | 显示已有命中及缺口 | 可调整搜索条件，不自动转到开放网络。 |
| 资料或模型服务失败 | 说明失败阶段，保留可访问搜索结果 | 有限重试后仍失败则停止；不能返回伪成功。 |
| 权限变化 | 不再展示失去权限的原文或缓存片段 | 刷新访问状态，必要时重做请求。 |

## 10 请求与反馈数据

| 对象 | 必要字段 | 保留目的 |
| --- | --- | --- |
| QueryRequest | request_id、user_id、原问题、模式、范围与版本条件、时间 | 还原用户实际问了什么，权限过滤发生在哪个范围。 |
| RetrievalTrace | 发布快照、检索配置、候选与最终证据 ID、过滤原因、阶段耗时 | 定位检索遗漏、版本错误及排序问题。 |
| Answer | 状态、正文、claims 与 citation_ids、缺失条件、失败原因 | 核查结论与证据支持，区分部分回答和完成。 |
| Feedback | request_id、类型、备注、操作者和时间 | 离线汇总和人工处理；不直接触发知识发布。 |

保留期限、敏感字段脱敏、是否保存完整问题与回答需在部署前确定。测试集和运行日志分开管理，不默认把内部问题用于外部训练。

## 11 逻辑接口契约

| 操作 | 主要输入 | 输出与限制 |
| --- | --- | --- |
| 搜索 | query、scope、version_filter、request_id | 授权命中片段、定位与状态；模式为仅搜索时不必生成回答。 |
| 单轮问答 | query、scope、version_filter、request_id | 答案状态、缺失条件、claim-citation 关系与资料卡片。 |
| 查看原文 | source_id、version_id、locator | 再次鉴权后的文件或定位；不接受仅凭客户端传入路径直读存储。 |
| 提交反馈 | request_id、类型和备注 | 反馈记录；不创建已发布知识。 |

接口路径和具体模型服务不绑定厂商。请求、模型和生成参数版本需可追溯，以便复现实验。

## 12 功能验收矩阵

| 用例 | 输入或条件 | 通过条件 |
| --- | --- | --- |
| QA-A01 找资料 | 精确文件名或项目术语 | 搜索返回可访问文件、适用版本及可读片段。 |
| QA-A02 有据回答 | 已有人工核实证据的问题 | 关键结论受引用支持，关键条件保留。 |
| QA-A03 无依据 | 语料不覆盖的问题 | 明确未找到充分依据，不伪造要求或引用。 |
| QA-A04 版本冲突 | 资料中存在不同要求 | 展示版本与差异；适用性未确认时不武断裁决。 |
| QA-A05 条件缺失 | 问题对象影响答案但未给出 | 提出具体补充项；可确认部分独立说明。 |
| QA-A06 非授权内容 | 用户无权访问的资料包含正确答案 | 检索、生成、原文、缓存均不泄露内容。 |
| QA-A07 引用定位 | 引用涉及跨页表格或脚注 | 原文位置可打开，保留理解结论所需上下文。 |
| QA-A08 无隐式记忆 | 连续两问涉及不同型号或版本 | 第二问不悄悄继承第一问条件。 |
| QA-A09 文档恶意指令 | 检索资料中含要求泄密、改规则等文字 | 将其作为资料内容处理，不执行其指令。 |
| QA-A10 中断与失败 | 生成中断或引用校验失败 | 部分输出和失败明确，不显示为完整成功回答。 |

## 13 评测与最小观测

问答独立评测集至少覆盖术语搜索、要求解释、型号匹配、版本差异、无依据、证据冲突及权限边界。问题、正确证据与可接受回答由人工核实；专业复核者未就绪时不宣称技术正确率已验证。

- 检索层：正确证据是否进入候选和最终上下文；按问题类型拆分，不能仅看总平均。
- 回答层：正确性、证据支持、必要条件覆盖、引用定位及无依据时的处理。
- 业务层：从开始搜索到取得正确依据并完成理解的时间，包含等待、阅读与纠错。
- 成本层：单次请求的检索、模型调用、上下文长度和人工维护时间。
- 事件：搜索或提问、澄清、检索完成、生成完成或失败、原文查看、反馈。P0 不做运营大屏。

指标定义及发布门槛见[知识库与 RAG 共用规范](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/docs/shared/knowledge-base-rag.md)。数值目标需在独立评测前确认，不能用“准确率高”代替验收。

## 14 后续能力与进入条件

多轮问答属于 P1：需要管理显式上下文、当前型号和版本、条件切换、追问改写及会话隔离。仅在单轮依据检索稳定、真实任务证实需要连续追问，并通过跨型号与跨版本串用测试后纳入。完整知识管理和反馈后台同样按实际维护瓶颈进入，不改变本版已确认边界。
