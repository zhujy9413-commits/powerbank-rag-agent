# 工作流与验证方法补充

日期：2026-10-27。用户提供了“任务表更新”原型作为方法参考。以下只吸收工作流和验证经验，不将参考项目的业务数据、模型表现或工具要求迁移为充电宝项目的事实。

## 1. 对当前产品的作用

| 参考项目的观察 | 对本项目的启发 | 当前处理 |
| --- | --- | --- |
| AI输出建议，只有人工逐字段确认才改变正式任务表 | 模型发现、人工判断及最终评审状态分开 | AI Work PRD已保留独立复核状态；后续实现需验证只作用于被确认项目 |
| 输出结构全部通过，仍出现进度、验收条件与不同客户范围混淆 | 引用存在、JSON正确都不能代替语义正确 | 当前原型只校验引用ID和摘录；语义仍标为待复核，不宣布专业结论通过 |
| 确认责任人时必须验证日期仍不变 | 单项操作不能连带改变邻近记录 | 后续报告评审验收增加端口、规则、记录之间的隔离检查，不增加本轮开发范围 |
| 未确认建议、原建议、人工修改与否决理由均保留 | 人工复核不能覆盖模型原始发现 | AI Work实现时保留原发现、最终决定、理由、操作者及时间；缺失或未决项不得改成通过 |
| 保存重载、重复导入、同编号异文冲突均经实际网页验证 | 失败恢复需要比较实际前后状态 | 报告任务按输入修订、依据快照、运行记录保存；重试保留原运行，重复提交不覆盖人工决定 |
| 同输入对照中有改善也有退步，同版重跑也可能措辞变化 | 固定输入、提示词和模型后，再比较效果与稳定性 | 当前新增真实生成请求的提示词及规范化请求体SHA-256；真实模型A/B对照仍待配置后执行 |

## 2. 后续评测要保留的区分

- “记录存在”“已执行核对”“未发现问题”“人工确认通过”分别记录，不能互相替代。
- 条件只完成一部分时，展示尚未满足的条件。例如温度记录齐全不能代替外观观察，A1记录不能代替C1。
- 不因某规则出现了支持证据就删除冲突证据；报告摘要与明细不一致时保留双方。
- 比较提示词时固定题目、证据、语料和模型配置，至少保留一个与本次修改无直接关系的回归案例。
- 保存所有实际输出和失败；不修改预期答案来迎合结果，不以建议条数或格式通过率证明判断质量。

这些是验证方法，尚未产生新的充电宝模型效果数据。当前仍为关键词检索基线，19项功能与接口测试使用本地模拟响应。
