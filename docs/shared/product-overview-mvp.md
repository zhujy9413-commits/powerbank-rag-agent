# 产品总览与 MVP 范围

版本：v1.0 · 2026-10-26 · 需求设计基线，待实现与验证

本文保留最初产品总览。当前细化范围、分期、页面和验收以[AI Work PRD](../ai-work/PRD.md)及[内部智能客服PRD](../internal-assistant/PRD.md)为准，原始假设和历史验证安排保留编制时状态。

一个内部工作台，两条业务流程。用可追溯的知识帮助资料查找与报告评审。

## 01 产品定位与证据基础

**充电宝研发评审与知识助手**服务中国大陆充电宝业务中的内部产品、研发与测试人员。第一版聚焦整机保护功能，包含 AI Work 测试报告辅助评审和内部知识检索与问答。

| 类型 | 当前基线 |
| --- | --- |
| 已确认的业务背景 | 用户在 2022—2024 年前后参与过充电宝项目，以规格书、相关标准与内部规范评审公司内部测试报告。该时间描述经历，不等同于标准版本。 |
| 已确认的问题 | 资料整理繁杂，参数冲突、是否满足要求及验证证据缺失容易遗漏，问题可能较晚暴露。现无频次、耗时及损失金额的量化基线。 |
| 已确认的使用方式 | 使用最新一版 PDF 测试报告；对象为组装完成的充电宝整机；评审结果供人工复核并导出。 |
| 证据边界 | 依据来自对既往工作的描述，尚无可用企业历史报告、当前组织访谈或真实运行数据。本文不将业务收益写成已发生的结果。 |
| 设计建议 | 统一工作台、单轮问答 P0、单一 Excel 导出、简易知识维护工具。文档解析范围和规则白名单需以代表性材料验证。 |
| 未定约束 | 部署环境、模型与工具、并发、成本预算、性能门槛、真实试点人员及具体标准基线尚未核定。 |

> 需求设计基线 v1.0，尚未开发和实测。本文中的“合规”具体限定为已确认适用依据下的资料符合性核对，不生成认证、量产放行或整机安全保证。

## 02 主要假设与验证任务

**主要假设 H1：**在充电宝整机保护功能相关的内部资料查找和测试报告评审中，基于受控资料提供引用、逐项核对与人工复核，可以减少核对遗漏，并降低完成任务的总耗时。两条流程分别评价，不能用问答成绩替代报告评审效果。

| 任务 | 用户完成的事 | 需要观察的结果 |
| --- | --- | --- |
| 知识检索与问答 | 找到适用要求、理解资料并定位原文 | 正确完成资料查找任务的时间、回答与引用正确性。 |
| 报告评审 | 确认依据、核对报告并形成可复核问题清单 | 复核后漏检、误报及包含复核和纠错的总耗时。 |

支撑假设包括文档能够被可靠解析、依据可取得且适用性可确认、检查规则能明确表达。资料来源和专业判断未就绪时，仅做流程与技术验证。

## 03 明确不做及理由

| 本版排除 | 理由 |
| --- | --- |
| 海外市场与其他硬件品类 | 保持单一业务领域，避免资料与规则范围失控。 |
| 历史报告自动对比 | 当前流程只核对用户选定的最新报告。 |
| 整改派单、复测管理、问题关闭 | 首版止于问题复核及导出，不扩展为项目管理系统。 |
| 自动认证、放行和改板设计 | 现有输入与权限不足以承担这些决定。 |
| 开放式联网补齐依据 | 首版仅使用审核发布或任务内确认的资料，便于追溯。 |
| 任意 PDF 的波形、照片和复杂图形自动判读 | 首版没有证据支持普遍视觉判读能力；相关项目显示证据或解析不足。 |

## 04 最小可用流程

1. 知识维护：获得允许使用的资料 → 导入解析 → 人工检查来源、版本及内容 → 发布索引。
2. 智能客服：输入搜索词或问题 → 限定范围与版本 → 检索 → 查看片段或带引用回答 → 查看原文或记录反馈。
3. AI Work：上传最新报告 → 确认解析、型号、依据和检查清单 → 逐项检索与核对 → 查看证据和未完成项 → 人工复核 → 导出。

待评审报告默认只在当前任务中使用，不直接进入公共知识索引。已发布依据、用户确认的任务附件和报告证据均保留来源类型。

## 05 P0 业务功能与验收

| 功能 | 优先级 | 解决的问题 | 为什么现在做 | 验收标准 |
| --- | --- | --- | --- | --- |
| 搜索与单轮问答 | P0 | 内部资料难找、难理解 | 直接验证知识检索价值 | 授权用户可搜索已发布资料；回答关键结论有可打开的引用；无依据时明确缺失。 |
| 报告逐项核对 | P0 | 冲突、不符合及缺证容易遗漏 | 直接验证评审价值 | 按已确认清单逐项记录结果；未配置、失败和未检查均单列，不计作通过。 |
| 依据与证据查看 | P0 | 无法确认判断来源 | 是结果可复核的必要条件 | 每项可查看资料版本、原文位置和报告证据；不适用或冲突依据会阻止确定判断。 |
| 人工复核 | P0 | 系统发现仍需业务确认 | 使输出进入真实评审流程 | 可确认、排除或暂无法确认并填写理由；保留原始结果与修订记录。 |
| 单一格式导出 | P0 | 问题清单需要带到评审会 | 闭合交付流程 | 导出 Excel 中含依据、范围、问题与复核状态；未复核与未完成内容有标记。 |

P0 是本次验证必需，开发顺序单独管理。客服入口的复杂多轮上下文属于 P1；本次对话本身的轮次不改变产品首版的单轮范围。

## 06 P0 技术依赖的最小程度

| 依赖 | 最小实现 | 暂不开发的完善部分 |
| --- | --- | --- |
| 解析、切分、索引 | 管理员导入，预览并纠正关键解析，建立有原文定位的索引 | 面向所有员工的批量自助上传、任意格式兼容。 |
| 来源及版本 | 保存必要元数据；发布前人工确认；任务固定依据快照 | 自动抓取、换版、可视化回滚和复杂审批流。 |
| 完整 RAG | 资料处理、检索、排序、证据组织、生成、引用核验、评测 | 复杂自主查询规划、自动调参与多代理协作。 |
| 权限与任务隔离 | 基于实际身份过滤可访问知识和任务附件，原文链接同样校验 | 复杂组织层级、多租户计费及企业级权限配置。 |
| 记录与评测 | 保存请求、所用证据、失败、耗时及人工判断，可离线统计 | 完整反馈中心、运营看板和实时大屏。 |

管理员的人工导入、检查和维护时间需计入总成本。权限、版本和证据不能因管理界面后移而取消。

## 07 P1、P2 与重启条件

| 能力 | 优先级 | 进入条件 |
| --- | --- | --- |
| 多轮追问与上下文处理 | P1 | 单轮检索引用已稳定，出现连续追问的真实任务证据，并通过跨型号、跨版本串用测试。 |
| 完整知识管理后台及审批流程 | P1 | 管理员的手动维护已成为可测量的效率或错误瓶颈。 |
| 自动更新、版本回滚界面 | P1 | 资料更新频繁且已有明确发布责任和回归流程。 |
| 复杂扫描件 OCR 和更多格式 | P1 | 代表性输入证实是核心使用阻塞，且关键数值识别质量通过验证。 |
| 反馈中心与运营看板 | P1 | 最小记录不足以支撑稳定试用中的定位和处理。 |
| 历史报告自动差异比较 | P2 | 出现持续的跨轮次比较任务，且单报告核心假设成立。 |

## 08 开发顺序与阶段门槛

| 阶段 | 产出 | 下一阶段前的判断 |
| --- | --- | --- |
| S0 资料与规则准备 | 合法可用的小规模语料、人工核实的检查项、标注样例 | 来源、适用性、预期检查清单及证据标注可追溯。 |
| S1 共用检索与引用 | 解析、索引、授权检索和原文查看 | 正确依据能被找出，未授权及失效资料不会进入证据集合。 |
| S2 单轮智能客服 | 搜索、回答、缺证提示、简单反馈 | 在独立评测集上评估检索、回答及引用；不能仅用演示问题。 |
| S3 报告评审 | 输入确认、逐项检查、异常与中断处理 | 核对结果与人工标注逐项比较，失败项目可识别和恢复。 |
| S4 复核与交付 | 复核记录、Excel 导出、对照评估 | 含人工成本的任务效果达到预先确认的门槛。 |

阶段表示依赖顺序；排期在资料、团队和选型明确后评估。

## 09 假设验证方案

| 项目 | 设计 |
| --- | --- |
| 对象与材料 | 问答任务和报告分别建立有正确依据、无依据、冲突、版本差异、解析缺陷等分组；模拟材料标注来源性质。 |
| 流程验证 | 用人工辅助的端到端样例检查流程和输出；人工参与的效果不当成自动化能力。 |
| 对照方式 | 具备条件后，采用可比任务的人工流程与 AI 辅助流程对照。采用不同但等价材料或平衡顺序，降低重复阅读带来的学习效应。 |
| 主要指标 | 两条任务分别统计正确完成情况、总耗时；报告另统计漏检与误报，不能只看采纳率。 |
| 观察窗口 | 流程验证、离线评测、真实小范围试用分别记录；试用人数、任务量和时间窗在招募与材料可用后预先确认。 |
| 支持继续 | 独立复核显示核心质量达标，并在计入复核与纠错后节省时间；运行及维护成本可接受。数值门槛须在正式评测前确定。 |
| 调整或停止 | 能找资料但核对误报负担大时缩减自动检查项；关键依据不可取得或严重错误无法控制时停止该项自动判断。 |
| 证据不足 | 只有模拟例子、样本不足、无专业标注或无可比基线时，保留待验证状态，不宣称已降本或减少改板。 |

功能交付通过不等于业务假设成立。详细指标、数据分组与发布门槛见[知识库与 RAG 共用规范](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/docs/shared/knowledge-base-rag.md)。

## 10 成本、可行性与未决项

建议有条件推进需求与原型验证。先取得允许使用的资料、建立有限规则清单及评测集，再投入自动核对实现。主要成本来自资料整理、标准授权或获取、文档解析、索引与模型调用、标注复核及日常维护。

| 未决项 | 当前处理 | 解锁条件 |
| --- | --- | --- |
| 具体适用标准、版本与检查白名单 | 先定义规则结构，不承诺覆盖所有保护测试 | 由资料来源与具备相应能力的复核者确认条款、适用条件和样例。 |
| 真实报告与专业评测资源 | 使用有标记的模拟材料做初验 | 具备合法真实材料和独立专业复核后，才验证真实业务效果。 |
| 扫描件占比、篇幅和表格复杂度 | 限制为能核实解析结果的输入 | 代表性语料测试后决定 OCR、文件大小、页数及复杂布局的支持范围。 |
| 部署、模型、并发与预算 | 保留适配接口，不绑定供应商 | 试点前核定数据流向、可接受成本和任务性能门槛。 |

改板次数受设计、测试覆盖和项目阶段等因素影响，暂作为长期观察项，不能直接归因给本工具。
