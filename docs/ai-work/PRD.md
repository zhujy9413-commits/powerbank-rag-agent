## 01 目标、边界与依赖

面向国内充电宝整机保护功能测试，帮助硬件产品经理在研发评审前，对照适用标准、公司测试规范及产品规格书核对最新 PDF 报告。核心目标为减少资料核对遗漏及缩短包含复核在内的任务耗时。

- P0：已配置项目的逐项核对、依据与证据查看、人工复核、单一 Excel 导出。
- 本版不做历史报告对比、整改闭环、认证放行和改板建议。
- 仅对可取得并核实的规则白名单提供自动检查；未配置的保护项目明确标为不支持自动判断。
- 知识发布、权限、RAG、版本和公共指标遵循[知识库与 RAG 共用规范](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/docs/shared/knowledge-base-rag.md)。

> 这是可实施的需求设计稿，不代表检查规则集、标准授权、开发或真实评测已经完成。

## 02 用户、前提与端到端场景

| 角色 | 职责 | 权限边界 |
| --- | --- | --- |
| 评审使用者 | 创建任务、确认报告和依据、复核与导出 | 仅访问授权任务和资料；身份由实际部署的认证机制提供。 |
| 专业复核者 | 确认规则适用性及争议发现 | 不凭角色名称假设已有人选；同一人可兼任，专业复核条件须在试点前落实。 |
| 知识维护者 | 维护已核实依据和已发布规则 | 通过简易工具完成入库与发布，完整审批后台是 P1。 |

1. 上传本人选定的最新报告，并确认型号和文件身份。
2. 检查原文与解析结果，纠正影响判断的数值、单位及测试项目。
3. 确认依据版本、规则适用条件和本次预期检查清单。
4. 系统逐项检索报告证据和依据，执行可检查的规则。
5. 查看发现、缺证、超范围及失败项目，逐条人工复核。
6. 导出问题表供评审会使用；任务复核完成不表示整改关闭。

## 03 页面与交互

| 页面 | 主要内容 | 动作 | 空态或异常 |
| --- | --- | --- | --- |
| 评审任务页 | 任务名、型号、文件、创建时间、状态和未完成项 | 新建、查看、恢复；无批量项目管理 | 无任务时说明所需材料；无权任务不展示。 |
| 解析与依据确认页 | 原始 PDF、解析字段、原文定位、依据版本、预期清单 | 修正字段、选择依据、排除不适用项并填写理由、确认开始 | 关键字段未确定时，相关检查项阻塞；无法确认完整清单时显示范围未确认。 |
| 评审结果页 | 范围概览、逐项结果、原文证据、复核状态、未完成项目 | 筛选、展开证据、复核、记录原因、导出 | 部分失败仍展示已完成结果；未完成内容显著标注。 |

保留明确的系统处理阶段和用户可执行动作。系统内部的模型名称、向量参数与检索得分不进入普通评审主流程。

## 04 任务输入与字段

| 字段 | 必填或处理方式 | 校验与来源 |
| --- | --- | --- |
| task_id / revision | 系统生成 | 任务及输入修订唯一标识，输入变化不覆盖既有运行结果。 |
| 任务名称 | 自动生成，可修改 | 不能作为报告身份或产品匹配的唯一依据。 |
| 产品型号 | 开始相应检查前确认 | 从报告提取并由用户确认；与规格书型号不符时阻塞相应检查。 |
| 报告文件 | 必需，一份主报告 | 记录哈希、文件名、页数、上传时间和存储位置；不自动认定公司最新版本。 |
| 报告编号 / 版本 / 日期 | 有则提取 | 缺失时显示未提供；编号缺失本身不自动判产品不符合。 |
| 规格书及版本 | 按检查项需要提供 | 可引用已发布文件，或作为仅当前任务可用的附件。 |
| 标准与内部规范 | 按检查项选择和确认 | 保存文档、版本、条款、适用范围及本次采用理由。 |
| 检查项目与适用性 | 检查前确认 | 来自已发布规则白名单；不适用或排除项目需保留理由。 |
| 结构、端口、条件等参数 | 按规则依赖收集 | 不能由系统为满足规则自行猜测；缺失转为适用性待确认。 |

文件大小、页数、处理时间上限与支持布局需用代表性语料确定。实现中使用可配置限制，界面在上传前说明，本文不虚构具体数值。

## 05 解析范围与输入确认

- 输入基线建议为可提取文本及表格的 PDF。扫描页可做 OCR 候选提取，但未通过关键字段核验时不能用于确定判断。是否纳入稳定支持范围取决于语料验证。
- 保留章节、页码、表格表头、行列、单位、脚注及测试项目上下文，不能只抽取分散数字。
- 关键字段包括测试对象、端口、条件、阈值来源、实测结果、单位、时间及现象记录。每个字段带原文位置和解析状态。
- 修正解析值时保留原始值、修正值、操作者和时间；不改写原 PDF。
- 仅有波形图片或照片而缺少可核实文字、数据时，显示相关证据尚未被系统验证。
- 缺页、损坏、密码保护或不可读文件无法继续自动检查时，指出具体恢复方式。

解析质量状态使用“已识别、待确认、无法识别”等可操作状态；未校准的模型分数不得作为内容正确概率展示。

## 06 任务与项目状态

| 任务状态 | 触发条件 | 下一动作与限制 |
| --- | --- | --- |
| 解析中 | 文件校验通过并开始处理 | 可查看进度；尚不可生成完成结论。 |
| 待确认输入与依据 | 解析结束或输入被修订 | 确认型号、字段、依据和范围；阻塞项可补充。 |
| 检查中 | 确认后的输入快照启动运行 | 运行绑定 revision、规则集和知识发布版本。 |
| 待人工复核 | 自动检查完成或部分完成 | 显示每项成功、失败与未检查状态，允许复核和带标记导出。 |
| 复核完成 | 所有需要复核的发现均有处置，未解决项有明确记录 | 允许存在已说明的证据不足；此状态不等于所有检查通过。 |
| 处理失败 | 任务级依赖或系统失败 | 保留结果与原因；修正条件后新建 run 重试，避免重复覆盖。 |

每个检查项另外保存执行状态 pending / running / completed / failed / not_checked。部分失败不被任务级完成状态掩盖。输入、依据或规则发生变化时生成新的修订或运行，旧结果标为历史运行且可追溯。

## 07 预期清单与适用性

1. 先从受控规则目录选择候选保护测试项目。
2. 根据产品型号、结构、端口及采用依据核实 applicability，区分适用、不适用、待确认。
3. 适用项按规则定义需要的测试对象与条件建立预期检查单元。
4. 将单元与报告中找到的证据映射。检索未命中仅表示未找到证据，不等于实际未测试。
5. 用户确认检查范围；未知、排除及未配置内容列入范围说明。

完整性结论仅对已确认的预期清单成立。RAG 负责找证据，不能通过一次相似度搜索证明全部标准条目已被覆盖。

## 08 规则结构与判定逻辑

| 规则类型 | 输入条件 | 处理与输出 |
| --- | --- | --- |
| 条件匹配 | 依据要求和报告条件均可识别 | 条件等价才继续结果比较；不一致显示条件冲突或无法直接判断。 |
| 数值或范围比较 | 量的含义、对象、单位、阈值来源及条件已确认 | 使用可复核的计算或规则执行，保存原值、换算和比较式；不满足前提时不强行比较。 |
| 资料一致性 | 同一参数语义、对象、条件可对齐 | 发现不同值或摘要与正文矛盾；不同条件下的差异不自动认定冲突。 |
| 证据完整性 | 已确认预期字段或检查单元 | 找不到必要证据时标缺失，列出需要补充的信息。 |
| 结果与结论一致性 | 结论及支持它的数据或记录可定位 | 检查“通过”等结论是否与证据矛盾；仅缺证时显示证据不足。 |

每条规则保存 rule_id、版本、标准来源与条款、适用条件、所需字段、判定表达式、证据要求、例外及发布状态。规则目录不自动采用“更严格”或“更新”资料；冲突依据先确认。

> 首批具体测试条目尚未完成专业核实。端口短路保护是流程说明样例，不意味着全部短路测试条款、全部端口和所有产品形态已可自动判断。规则样例与真实标准条款必须分开标记。

## 09 本模块完整 RAG 链路

1. 输入处理：解析报告、任务依据和已确认清单，生成带对象与条件的结构化字段。
2. 按检查项构造检索请求：以项目、参数、条款、对象、条件和版本查找依据及报告证据。
3. 范围过滤：报告及任务附件仅在当前授权任务内检索；公共依据只用所选快照中的适用资料。
4. 召回与排序：关键词和语义召回结合，按适用性、条款及证据匹配排序，补充必要上下文。
5. 证据组织：每项分别绑定要求证据和报告证据，保留相互独立的来源身份。
6. 核对与生成：规则或计算执行明确比较，模型协助字段对齐和说明；不明确的解释标为待复核。
7. 引用与覆盖校验：检查引用身份和定位是否有效、结论是否有支持，并与预期清单对账。
8. 输出与观测：保存执行状态、发现、缺证、错误、耗时、复核及运行配置。

通用解析、切分、索引更新与权限策略见[知识库与 RAG 共用规范](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/docs/shared/knowledge-base-rag.md)。

## 10 结果模型与复核

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 检查结论 | 未发现问题 / 不符合 / 冲突 / 证据不足 | 仅对本次规则、条件和证据成立。 |
| 范围及执行 | 适用性待确认 / 不适用 / 未配置 / 未检查 / 失败 | 与检查结论分开，不能计为通过。 |
| 人工复核 | 待复核 / 确认发现 / 排除发现 / 暂无法确认 | 确认或排除均保留理由；结果改变不删除系统原始发现。 |

界面展示检查项目、要求、依据、报告条件与结果、发现说明、双方证据位置、待补信息和复核意见。概览只统计本次范围，不生成整机安全评分。

对发现项目默认待复核。用户可以确认发现、排除发现或保留无法确认；纠正数据和依据后需要新运行才能改变系统判断，不允许仅修改标签伪装重新检查。

## 11 Excel 导出规范

- 首版导出一份 Excel 工作簿，包含任务与范围说明、逐项检查及问题复核记录。
- 保存产品、报告身份、run_id、生成时间、依据与规则版本、适用和排除项、未配置及失败项。
- 每行保留要求、报告证据、来源名称与页码、结果、复核状态及备注。链接之外仍有可读定位信息。
- 未复核结果和未完成内容明确标记。任务能导出不代表全部项目通过。
- 导出内容遵循任务权限；从用户输入写入单元格的文本按文本处理，防止被当作公式执行。
- 私有原文链接仍需鉴权，不生成永久公开下载地址。

以下描述产品层服务契约，不锁定框架；接口路径为建议，开发时可映射。所有接口在服务端校验身份、对象访问权和输入修订。

| 操作 | 主要输入 | 输出与错误要求 |

## 13 异常与恢复

| 触发 | 系统行为 | 恢复方式 |
| --- | --- | --- |
| 文件损坏、加密、不可读 | 停止解析并说明原因 | 提供可读版本，保留失败记录。 |
| 扫描或表格关键字段不清 | 阻塞受影响检查项，标出位置 | 人工确认字段或补充文字数据。 |
| 对象、版本或依据冲突 | 不产生受影响项目的确定结论 | 确认适用资料或缩小范围。 |
| 依据缺失 / 检索无证据 | 显示证据不足并列待补项 | 补充材料后重新确认、运行。 |
| 模型返回格式或引用非法 | 校验失败，有限重试；仍失败则标失败 | 保留原文与已完成项目，允许人工核查。 |
| 超时、服务不可用 | 任务或项目显式失败，保存进度 | 依赖恢复后重试，新运行可追溯。 |
| 资料在运行后被停用 | 保留任务证据身份，标明资料状态变化 | 复核者判断是否重新运行；访问仍按现时权限检查。 |

| AW-A06 解析阻塞 | 关键数字无法识别 | 相关项不可输出确定结论；人工修正确有记录。 |
| AW-A07 范围覆盖 | 包含未配置与失败项目 | 概览、明细、导出均保留相应范围状态。 |
| AW-A08 复核 | 人工排除一条发现 | 理由及原始发现同时可追溯。 |
| AW-A09 版本修订 | 输入或所用规则改变 | 新运行与旧运行分开，不能把旧结果当新结果。 |
| AW-A10 导出与权限 | 有待复核和失败内容的任务 | Excel 标记完整、定位可读；无权用户不能获取文件或证据。 |
| AW-A11 重试 | 同一启动请求重发 | 不会无提示产生重复业务运行；失败恢复保留原记录。 |

## 15 观测、效果与发布前提

- 事件：创建、解析完成、字段修正、范围确认、检查启动、项目完成或失败、证据查看、复核处置、导出。均关联 task_id、run_id 和适用配置。
- 质量：基于人工核实的问题集合统计漏检、误报及错误分类；证据不足与失败单独统计，不剔除后美化成绩。
- 效率：从用户开始准备输入到获得可用、已复核输出的总耗时，包含上传、阅读、等待、纠正和导出。另记录系统处理时间。
- 成本：计入解析、模型、索引检索、存储及管理员与专业复核的人工时间。
- 发布前需落实真实规则白名单、标准使用权限、专业标注、代表性 PDF 支持范围、数值门槛和部署条件；目前均不宣称已达成。
