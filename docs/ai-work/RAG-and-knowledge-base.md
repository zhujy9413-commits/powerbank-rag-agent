## 本模块应用链路

1. 输入处理：解析报告、任务依据和已确认清单，生成带对象与条件的结构化字段。
2. 按检查项构造检索请求：以项目、参数、条款、对象、条件和版本查找依据及报告证据。
3. 范围过滤：报告及任务附件仅在当前授权任务内检索；公共依据只用所选快照中的适用资料。
4. 召回与排序：关键词和语义召回结合，按适用性、条款及证据匹配排序，补充必要上下文。
5. 证据组织：每项分别绑定要求证据和报告证据，保留相互独立的来源身份。
6. 核对与生成：规则或计算执行明确比较，模型协助字段对齐和说明；不明确的解释标为待复核。
7. 引用与覆盖校验：检查引用身份和定位是否有效、结论是否有支持，并与预期清单对账。
8. 输出与观测：保存执行状态、发现、缺证、错误、耗时、复核及运行配置。

通用解析、切分、索引更新与权限策略见[知识库与 RAG 共用规范](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/docs/shared/knowledge-base-rag.md)。

### 知识库与 RAG｜共用产品与验收规范

版本：v1.0 · 2026-10-26 · 需求设计基线，待实现与验证

统一管理资料、证据和版本，为问答与报告评审提供两条完整检索链路。

## 01 共用底座的职责

提供文档处理、受控发布、检索、原文定位、版本、权限和观测能力。智能客服以问题为检索单位，AI Work 以确认后的检查项为检索单位；共用索引不代表共用同一套生成提示、检索过滤条件或评测结果。

| 资料集合 | 用途 | 可见范围 |
| --- | --- | --- |
| 已发布知识 | 规格书、适用标准和公司测试规范 | 按用户授权、适用范围和版本检索。 |
| 任务内依据 | 某次评审确认但尚未公共发布的附件 | 仅授权任务可使用；不自动进入公共检索。 |
| 待评审报告 | 本次被检查的输入及证据 | 仅当前任务，不能同时作为证明自身正确的规范依据。 |
| 评测资料 | 公开材料与标注的模拟、真实测试集 | 测试权限单独控制；模拟规则不得混入生产发布目录。 |

> “完整 RAG”在本项目中包括数据准备到评测的全流程。自动知识审批、复杂查询规划与运营大屏属于可后移的产品完善功能。

## 02 文档及版本元数据

| 字段 | 要求与用途 |
| --- | --- |
| document_id / version_id / content_hash | 文档逻辑身份、版本身份和文件内容校验；同名文件不视为同一版本。 |
| title / document_type / source_type | 名称、标准或规范或规格或报告类型、来源性质。 |
| source_origin / usage_rights | 原始来源、允许的使用范围；公开可查不自动等于可任意复制全文。 |
| standard_number / edition | 有则记录完整编号与版本，不能仅保存“22 版”等口语简称。 |
| publish_date / effective_date / status | 已知则保存发布与实施信息；未知明确标记，不由模型编造。 |
| market / product_scope / model_scope / applicability | 市场、整机或组件、型号及适用条件；充电宝整机与电芯、电池组不能仅按相似术语混用。 |
| owner / reviewer / reviewed_at | 维护责任、审核记录与时间。P0 可工具登记，完整审批界面是 P1。 |
| access_scope / task_id | 授权范围与任务隔离标识。 |
| publication_id / index_revision / parser_version | 所处发布快照和索引、解析配置，便于复现。 |
| file_locator / page_count | 原文件位置和页数；业务界面不能暴露内部磁盘或存储凭据。 |

## 03 知识生命周期与发布

1. 导入：登记来源、权限及文档身份，进行文件校验和去重。
2. 解析：生成带定位的内容和解析异常清单。
3. 待核验：人工检查关键内容、版本和适用范围；未确认资料不进入默认检索。
4. 待索引：完成确认，生成切分、向量和文本索引。
5. 发布：索引与元数据准备完成后切换可见快照，避免半发布状态。
6. 停用或替代：从默认检索排除旧资料；保留获准保存的历史证据身份，访问仍受现时权限约束。

P0 以简易管理工具和可追溯记录完成发布，不要求自助审批系统。发布失败不改变当前可用快照；重试需要对同一文件与版本幂等。更新与撤销均触发相关缓存失效。

## 04 文档解析、切分与索引

| 环节 | 处理要求 | 异常与质量控制 |
| --- | --- | --- |
| 原文解析 | 保留章节、条款、页序、表格、单位和脚注，删除明确页眉噪声但不损失条件 | 不可读、疑似缺页或关键字段错位时进入人工确认，不当作成功全文。 |
| 表格处理 | 行内容必须带表头、单位及必要注释，保留跨页延续关系 | 无法恢复对应关系时保留原图位置并标记未验证。 |
| 条款切分 | 优先按完整语义条款、测试项目和必要上下文切分 | 不预设固定长度最优；尺寸和重叠策略通过证据检索测试。 |
| 上下文保留 | chunk 关联父章节与相邻必要内容 | 数值、对象、适用条件与例外不能分开后失去联系。 |
| 索引字段 | 内容、标题、条款、项目术语及过滤元数据，向量与全文索引关联同一内容版本 | 元数据及权限缺失的块不得发布。 |
| 向量化 | 记录 embedding 配置与维度，绑定对应内容和模型版本 | 配置改变需重新索引或并行索引，不混用不兼容向量。 |
| 更新发布 | 使用新 index_revision 校验后再切换 | 旧快照继续服务直至切换成功；历史任务仍可解析原来源身份。 |

已发布标准正文与私有报告可复用解析逻辑，权限和检索集合必须分开。解析/OCR 的人工修正保留来源与修订记录，不能无痕替换原文。

## 05 两条检索链路与候选排序

| 阶段 | 内部智能客服 | AI Work 报告评审 |
| --- | --- | --- |
| 查询单位 | 当前单轮用户问题 | 预期清单中的单个检查项与所需证据。 |
| 查询构建 | 保留型号、术语、单位及版本，必要时澄清 | 使用测试对象、条件、规则字段、条款和版本定位依据及报告证据。 |
| 过滤 | 授权范围、已发布状态、适用领域、版本及型号 | 相同过滤外，公共依据限所选快照，报告限当前任务。 |
| 候选召回 | 关键词与向量检索组合的候选集合 | 要求证据与报告证据分别检索，不相互混作依据。 |
| 排序 | 适用性和直接支持问题的程度优先 | 适用条件、规则字段和报告位置匹配优先，补齐相关表头或注释。 |
| 上下文组织 | 对结论需要的证据去重、补充上下文 | 每个检查单元保留要求、实际条件、实际结果与缺失字段。 |
| 生成与执行 | 有据回答，冲突并列，缺证说明 | 明确数值由规则计算；模型协助对齐和说明，存疑转复核。 |
| 校验 | 引用定位与支持关系 | 引用、比较前提与检查覆盖对账。 |

召回数量、排序模型、分数阈值、证据预算和重试上限均为待实验的配置。以人工标注证据评价选择，不把检索分数当成正确概率。若语料规模和任务验证表明简化检索已足够，可采用更低成本配置，同时保留证据和评测闭环。

## 06 证据与引用结构

| 对象 | 必要字段 | 规则 |
| --- | --- | --- |
| Chunk | chunk_id、document_id、version_id、parent_id、内容、locator、适用与权限字段 | 必须能回到相同版本原文。 |
| Locator | 文件页序、印刷页码（如可识别）、章节或条款、表格行列或区域 | 无法确定的定位字段留空，不伪造页码。 |
| Evidence | evidence_id、chunk_id、原文片段、定位、source_role、scope_id | source_role 区分要求、被核对结果和背景说明。 |
| Claim | claim_id、生成结论、citation_ids、支持状态 | 引用存在、定位可打开和支持关系分别校验。 |

引用校验先做 ID、版本、访问权与定位有效性检查，再评估证据是否支持结论。模型检查可作辅助，不能仅由同一个生成模型自评就宣布真实正确。证据不足的结论必须收敛为缺证、部分回答或待复核。

## 07 检查规则注册表

规则注册表与原文索引分开管理。RAG 负责找证据，规则表定义检查单元、前提、比较和异常处理。未完成来源或专业核实的规则不进入 active 状态。

| 字段 | 含义 |
| --- | --- |
| rule_id / rule_version / state | 规则身份、版本及 draft / verified / active / suspended 状态。 |
| source_document / version / clause / locator | 规则对应的原始要求及定位。 |
| test_item / object_scope / applicability | 测试项目、整机或组件对象，以及端口、结构等适用条件。 |
| required_fields / units / evidence_requirements | 需要抽取的字段、单位、必要记录和证据条件。 |
| comparison / exceptions / decision_outputs | 判定表达式、例外和允许输出状态。 |
| missing_policy / conflict_policy | 缺字段或来源冲突时如何停止相关判断、提示和恢复。 |
| verified_by / verification_record | 专业复核身份与验证依据；未落实时保持未指定。 |

保护功能首批白名单须结合可获取资料确认。报告完整性仅对已确认的适用检查清单负责，不能用规则注册表中的条目数量代表标准全部覆盖。

## 09 权限、隔离与输入边界

- 权限在服务端检索前和证据返回前校验。报告、任务附件、缓存、日志查看和导出均遵守相同授权，不仅隐藏界面。
- 索引与缓存键纳入授权范围、发布版本及任务身份；权限变更后不继续复用不匹配缓存。
- 单个任务材料不能进入其他任务或普通客服检索。保留历史证据不意味着永久保留访问权限。
- 文档及检索片段视为资料内容，其中要求泄密、改规则、调用外部工具等文字不能变成系统指令。
- 模型生成的查询或输出使用结构校验和允许字段；不直接拼接成可执行代码或任意数据库命令。
- 默认流程不自动对外发送报告、消息或通知；外部数据处理只在部署数据流获准后启用。
- 数据保留、删除、备份及模型服务数据政策在真实数据接入前核定，不虚构现有企业制度。

P1 的复杂组织权限配置不影响上述 P0 最小访问控制要求。

## 11 共用数据契约与一致性

| 对象 | 关键关系及约束 |
| --- | --- |
| PublicationSnapshot | 绑定一组可用 document_version 与 index_revision；发布原子切换。 |
| Task / InputSnapshot | 任务绑定原文文件身份、产品确认值、所选依据和清单；修改产生新 revision。 |
| Run | 绑定 task_revision、publication、rule_set 和模型/提示/检索配置；重试生成或恢复可识别运行。 |
| ChecklistItem | 绑定适用性、所需证据、执行状态及检查结果；未配置与失败不等于符合。 |
| Finding / ReviewRecord | 发现保留原系统输出；人工处置追加版本，不无痕删除。 |
| QueryRequest / Answer | 单轮请求绑定范围、证据、结论和状态；不隐式继承上一请求。 |
| OperationRecord | 发布、修改与复核动作带操作者、时间、对象及结果；保留期限待数据策略确定。 |

请求幂等防止网络重试造成重复写入；乐观并发检查用于输入确认及复核记录；生成完成前校验输出结构。记录不得包含访问令牌、密钥或非必要敏感内容。

## 12 分层评测与指标口径

| 层级 | 指标 | 计算或判定口径 |
| --- | --- | --- |
| 解析 | 关键字段正确、原文定位正确 | 与人工核实字段和位置比较；无法识别、人工修正及解析失败分别计数。 |
| 检索 | 正确证据召回、排序和最终上下文覆盖 | 按问题或检查单元的人工相关证据集评估。Recall@k 的 k 在配置中记录；无相关证据任务单列。 |
| 问答 | 结论正确、必要条件完整、引用支持 | 对事先标注的可接受回答逐项核查；可验证结论中被证据支持的占比作为支持率，不替代正确性。 |
| 无依据处理 | 无证据时正确提示、错误确定回答 | 对无答案、超范围或冲突任务单独统计，不混入正常有答案准确率。 |
| 报告检查 | 召回率、精确率及错误分类 | TP 为正确发现，FN 为漏掉的已知问题，FP 为误报；召回 TP/(TP+FN)，精确率 TP/(TP+FP)。分母为零时标不适用。 |
| 覆盖 | 已处理、未检查、失败与适用性未知 | 相对本次确认清单分别统计；被排除项目及原因也报告。 |
| 人工后效果 | 复核后仍遗漏、有效任务完成率 | 依据独立核实的最终输出，不能将采纳率等同于正确率。 |
| 效率 | 端到端任务总耗时、系统耗时 | 用户时间含准备、等待、阅读、复核、纠错和导出；系统从接收请求到完成或失败，失败任务不从统计中隐藏。 |
| 成本 | 每次问答、每份报告、每次知识更新 | 模型、解析/OCR、向量、存储检索与人工时间分项记录，避免只统计模型 token。 |

条件、版本与权限是必须单列的错误维度。若后续采用 P90 等时延指标，需同时报告计时起止、样本数、失败率和超时处理；当前不虚构数值门槛。

## 13 测试集与验证安排

1. 收集允许使用的代表性标准、规范、规格和报告；目前真实企业材料缺失，先用明确标注来源的公开与模拟材料。
2. 为问题标注正确证据、必要条件与可接受回答；为报告标注预期清单、已知问题及应有结果。
3. 覆盖精确术语、语义问法、版本冲突、无依据、任务隔离、表格错位、单位差异和结果矛盾等分组。
4. 区分配置调试集和独立评测集；按文档、型号或项目划分，避免同一证据复制到不同分组造成泄漏。
5. 规则和答案的专业正确性由具备相应能力的人核实；生成模型可协助造题，不能独立产生并证明金标准。
6. 离线评测用于验证技术链路和错误处理；具备真实任务条件后，再用可比任务进行人工与 AI 辅助对照。
7. 在正式对照前锁定任务样本、观察时间窗、指标、目标及可接受误报负担。样本不足只报告观察，不推断普遍收益。

模拟测试结果只证明被构造情形下的行为。真实试点的招募、样本量、时间窗和负责人尚未落实，保留为试点准备项。

## 16 成本、性能与可观测性

- 记录每次解析页数、OCR 使用、向量生成、召回与排序、模型输入输出、失败与重试、存储及人工修改时间。
- 以 query、task、run 和 publication 标识关联链路，支持定位检索错、解析错、适用性错和生成错。
- 缓存必须按授权范围、版本和配置隔离；不能为省成本混用任务数据。
- 索引更新可按内容哈希减少重复处理；模型和解析配置变化时重新验证相应缓存及索引。
- 上传限制、并发、预算、超时和有限重试由代表性任务测量后设置，并在用户等待或失败时说明状态。
- 初版使用可导出记录及离线表，不要求运营大屏；人工资料维护和专业复核仍算入投入。
