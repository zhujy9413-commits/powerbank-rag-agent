# AI Work｜PDF模板变体与条件冲突回归

v0.2 · 2026-10-28。适用于本机模拟评审原型；真实标准与专业验收仍未启用。

## 本轮解决的问题

首版依赖固定列序及单行数值，换列、单位换行或字段别名容易导致有记录却没有被解析。原先只在任务层确认5 V输出范围，没有逐条核对报告实际测试条件，可能将9 V、输入角色或多口组合记录用于当前规则比较。

本轮新增受控布局解析、候选记录覆盖审计和逐条条件核对。已定位但不能完整映射的内容单独显示，不再与报告本身缺记录混为一谈。没有明确条件，或条件与本次范围不同，相关单元停止比较。

## 支持的输入与保护行为

| 情况 | 当前处理 |
| --- | --- |
| 同行、分隔列、已识别表头下的列序变化 | 根据表头和记录结构映射端口、字段、值，保留原文 |
| 数值与单位分行 | 在同一记录的已识别值列内连接；不拿下一条记录的单位补齐 |
| 字段别名 | 支持“短路保护响应时间”“保护后恢复电压”两个受控别名 |
| 重复表头、全角字母数字 | 归一化用于匹配，引用仍保留原始PDF文字 |
| 跨页单位 | 仅在“续表A（接上页单位）”与前页待补单位记录唯一对应时连接；保留两页证据 |
| 未声明的跨页单位 | 显示孤立单位诊断，阻塞受影响单元；不猜测来源 |
| 无法映射、截断、未配置端口 | 展示记录候选及具体诊断；不把C10映射为C1，不静默忽略多余记录 |
| 声明页数与实际页数不同 | 显示报告不完整，相关核对保持未检查 |
| 无可提取文字的图片页 | 明示尚未OCR或核验；阻塞可能受影响的检查 |
| 数值缺单位或关键位模糊 | 保留记录，但不给出阈值比较结论 |

这些是有限布局和语法的支持范围，不能推广为任意PDF、任意复杂表格或任意扫描件解析能力。

## 解析覆盖怎样呈现

输入页新增“解析覆盖与测试条件”，显示候选数、已映射数、未映射数、诊断及对应PDF页。结果页增加独立解析诊断，受影响单元显示“未执行比较”。

以PV-15为例，正文中有9条带记录锚点的候选，8条能够映射，R09的“保护动作延迟”不在字段词表内。系统保留R09原文和诊断，阻塞A1相关核对，不再仅用已找到的R01直接输出正常结果。

候选审计只针对本版可识别的文字锚点和表格结构。它不能证明所有PDF内容均已识别；图片文字、完全陌生的布局及无法还原的语义仍需人工查看。已映射也不表示数值和条件已核实。

## 条件核对与冲突处理

当前模拟规则仅适用于A1、C1、5 V、输出角色、单口的端口短路保护已有记录。

1. 从报告明确的测试条件声明取得全局上下文；行内或紧邻记录的明确条件可覆盖对应维度，保留双方原文。
2. 逐条核对电压、角色、组合，缺少必要条件、存在互相矛盾的声明或超出范围时停止比较。任务清单“采用5 V”不能代替报告实际条件。
3. 摘要和明细还需核对环境条件。两者电压或环境不同，不把数值差异直接认定为同条件数据冲突。
4. 多条同端口、同字段记录具有不同条件时，不合并或挑选数值，先明确对应关系。重复记录ID则保留独立身份冲突。
5. 人工修改解析数值不能绕过条件核对；修正条件需要补充或更换有明确条件的报告。

| 例子 | 修复后的结果 |
| --- | --- |
| R01写80 ms，但相邻条件是9 V | 显示实际9 V，相关单元未检查，不与5 V规则的500 ms比较 |
| 条件为输入或多口组合 | 标条件不匹配，停止当前规则比较 |
| 摘要为9 V、明细为5 V | 摘要一致性项为证据不足；不直接称其为数值矛盾 |
| 摘要环境40℃、明细25℃ | 不认定同条件冲突；保留双方条件 |
| 全局同时声明5 V和9 V | 条件冲突，停止受影响比较 |
| 5.0 V与5 V、25.0℃与25℃ | 数值归一后视作相同条件 |

当前没有验证真实标准中复杂条件等价关系；也没有增加实验操作建议。

## 样本与对照设计

新增24份模拟PDF，共51个实际页面。全部由软件构造，没有使用企业历史资料。测试范围包括6类正常布局变体，以及跨页不明、超范围条件、摘要条件差异、未映射字段、截断、重复ID、缺页、图片页、未配置端口、缺单位、条件缺失、条件矛盾与非模拟模板。

完整清单、明确的期望及文件摘要见[样本清单](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/data/pdf-variants-v0.1/cases.json)，PDF见[样本目录](https://github.com/zhujy9413-commits/powerbank-rag-agent/tree/main/output/pdf/variants-v0.1)。

生产代码不读取此清单的期望、测试标签或评测结果。样本及期望是作者拟定开发集，已经用于定位和修复问题，不是独立测试集。

## 最终结果

修复前基线使用提交`acd883a69c597f5d8ce5d8318c1125f8b3e636e2`中的评审引擎。修复前后均读取最终嵌入字体的同一批PDF，清单摘要一致，未改变期望来适配输出。

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 满足完整场景期望 | 4 / 24 | 24 / 24 |
| 接受的模拟模板文件 | 22份 | 23份；另1份非模拟文件按预期拒绝 |
| 受支持、已标注文字记录的身份/端口/字段/值一致 | 145 / 180 | 180 / 180 |
| 指定阻塞行为实现 | 1 / 16 | 16 / 16 |
| 完整自动回归 | 首版62个测试方法 | 当前80个测试方法通过，新增18个，另含子用例 |
| 原始四页控制报告 | 原有12项参考 | 三次均保持12项结果和必要来源一致 |

180条的固定分母包含未成功处理文件中的可支持文字记录。早期运行自身只统计已进入解析的176条，因此最终比较统一补足固定分母；不因拒绝或失败而排除这些记录。无法映射字段、缺失页内容、图片页里的文字不计入这180条，分别验证诊断和阻塞，不能用180/180证明PDF全部记录完整。

24/24表示满足此开发集的解析、提示或阻塞期望，部分场景应当停止检查；不表示24份报告均通过评审。构造场景、代码和期望共享设计背景，不能据此宣称真实报告解析准确率或业务收益。

实际结果包括[修复前最终输入对照](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/eval-results/pdf-variants-final-input-baseline-v0.4.json)、[修复后结果](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/eval-results/pdf-variants-final-v0.5.json)、[80项回归记录](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/eval-results/pdf-variants-tests-v0.1.txt)和[控制报告结果](https://github.com/zhujy9413-commits/powerbank-rag-agent/blob/main/eval-results/ai-work-control-v0.2.json)。首次失败及中间结果继续保留。

初批样本存在未嵌入字体的问题，在PDF渲染检查中发现后改为嵌入字体。输入内容和期望保持不变，文件摘要因字体改变而更新。最终51页已重新渲染并检查；最终对照以v0.4、v0.5为准，早期v0.1至v0.3属于修复过程记录。

本轮规则检查未调用生成模型，新增模型请求为0；这不是新增的模型回答评测。仍保留专业复核待完成状态。

## 使用和兼容

刷新本机原型，在“报告逐项评审”上传样本即可查看新增诊断。Excel导出保留覆盖摘要、逐条实际条件、未检查状态及诊断，不将它们计作通过。

新解析器版本`controlled-pdf-v0.2`，模拟规则执行版本`synthetic-short-circuit-v0.2`。历史任务、运行和复核不被改写；旧解析快照不能直接用新引擎重跑，需要重新导入PDF建立任务，旧结果仍可查看。

## 复现

```bash
python3 -m pip install -r requirements-dev.txt
python3 -m unittest discover -s tests -v
python3 scripts/evaluate_pdf_variants.py --baseline-ref acd883a69c597f5d8ce5d8318c1125f8b3e636e2 --output eval-results/pdf-baseline-new.json
python3 scripts/evaluate_pdf_variants.py --output eval-results/pdf-after-new.json
```

构造脚本`scripts/build_pdf_variants.py`使用ReportLab、Pillow、pypdf与可嵌入的宋体；现有PDF已随仓库保存，日常评审只需原有pypdf依赖。构造脚本和评测脚本均拒绝覆盖既有产物。不要为复现而删除已有结果。

下一步应取得合法的、未经本轮调试的代表性报告，人工标注真实表格与条件，再开展独立验证。扫描件OCR、复杂合并单元格、任意跨页表格和正式标准规则不在本轮交付能力内。
