# P0修复后的第二批新样本留出评测

v0.1 · 2026-10-28。全部为构造资料，无企业历史数据。修复代码先冻结为`3b610efd128689e4a7fdca52ced14c3809091545`，之后才设计、生成本批PDF；被测应用v0.3及模拟知识依据均不再修改。

## 使用边界与独立性

本批20份PDF、40页只验证编号覆盖、图片核验提示、局部条件停止，以及必要的正向控制。数据与期望在首次调用被测引擎前另作冻结提交。原HO-01至HO-20已用于本次修复，属于开发/回归集；其首次12/20不改写，也不与本批合并成留出分数。

新样本仍由同作者、知晓实现的情况下构造，含定向异常和共享基础布局，是时间留出评测，不是外部独立测试、盲测、专业或真实业务验收。部分异常类别已在开发集中出现，未声称完全新类别或统计代表性。

运行固定Git提交的归档副本，子进程只接收PDF路径与ID。期望及评分仅在外层读取，不进入引擎或知识库。复用已验证的独立评分函数和归档执行器，未复用旧样本构造函数或旧数据行。模型请求为0。

## 固定口径

| 指标 | 预先确定的含义 |
| --- | --- |
| 场景 | 20个，包括正常比较、异常比较、未检查和可见提示；不是报告通过率 |
| 文字记录 | 205条，包含15条未批准或缺失编号的记录；不能因不支持编号而剔除分母 |
| 图内记录 | 3条，单独检查图片资源可见性及停止行为，不计入文字匹配 |
| 其他图片 | 1个装饰图；应明确待人工核验并停止，暴露当前保守策略对可用性的影响 |
| 未绘制资源 | 1份文件保留图片XObject但不实际绘制；应正常比较，防止仅看到资源名称就误报警 |
| 图片检查 | 每份文件的实际绘制图片数量应与预先标注相符，嵌套Form、内联图片均检查 |

“满足场景”要求：支持记录的ID/端口/字段/值与标注匹配；按预设执行正确比较或保守停止；需要覆盖诊断时必须显示具体问题。未知格式编号可不自动映射，但必须进入候选、提示未映射并停止受影响单元。该保守路径不意味着文字解析完整，遗漏仍进入205条分母。未来批准新编号格式后，应在下一轮协议中预先允许等价的完整解析行为。

图片没有OCR或人工内容确认，冻结策略为检测到实际绘制图片即停止10个配置单元；无法证明图片只涉及某端口，不猜测范围。即便是装饰图也会阻塞，此为明确的当前代价。未绘制资源不算待核验图片内容。

局部条件：已有明确绑定格式可以核对；脚注或声明无法唯一绑定时提示，已知记录ID只阻塞相应单元，明确端口只阻塞该端口；涉及未知对象或作用范围不明时全部停止。不得默认套用全局5 V。这里是作用范围的保护检查，不声称新增任意自然语言条件解析能力。

模拟阈值沿用原知识源：响应≤500 ms；恢复4.75至5.25 V；温升≤12 K。均为软件演示数值，不代表真实标准。

